Source and ABI review
- Both actual file-open sites are fixed: CsvDialog::analyzeFile and
  CsvSource::importData. Owning std::u8string explicitly preserves incoming
  UTF-8 code units before std::filesystem::path performs native conversion.
  This avoids Windows' narrow stream ANSI interpretation without changing
  CSV content decoding, timestamps, numeric locale, or stored config strings.
- The path temporary lives through stream construction; no borrowed pointer,
  new exported interface, vtable/layout change, allocator boundary, or host
  capability requirement is introduced. The minimum SDK remains unchanged.
- Missing-file is_open handling and empty-import handling remain in place.
  SDK 0.34.1 source and dialog trampolines catch exceptions inside noexcept ABI
  boundaries, including conversion errors. Incoming malformed UTF-8 JSON is
  rejected by JSON parsing; this change does not add an invalid-UTF-8 recovery
  contract or broader native-filename support.
- Existing numeric synthetic samples are checked exactly, not merely nonempty.
  Tests dynamically load the real plugin and exercise both preview and import.
- No APBIN/FFT changes, private records, private paths, field names, screenshots,
  runtime logs, or credentials occur in the patch. All fixture data is synthetic.
